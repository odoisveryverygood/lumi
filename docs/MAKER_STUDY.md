# Maker usefulness study — prepared, not run

No participants, interviews, time savings or human ratings are claimed. This is a protocol for the next validation step. The automated geometry benchmark does not establish product demand or usefulness to real makers.

Recruit three to five people who actually modify electronics assemblies or enclosures. Give them a small, realistic placement or clearance change using a source assembly and its component documents. Keep the goals concrete: preserve the case, place the specified component within the modeled region, preserve the other components, and identify what remains unverified.

Compare a matched task in their normal workflow with a task using Lumi. Alternate the order and use comparable variants so familiarity with the first task does not predetermine the second result. Keep access to the same source material in both conditions. Do not coach participants through the successful path while recording independent completion.

Record actual elapsed time, whether the named requirements were satisfied, accidental changes, requests for help, and whether the person correctly understood the remaining limits. Ask what they would need before trusting the result for their own project. Use anonymous participant IDs. Preserve unsuccessful attempts and report the small sample size alongside any result.

For visual quality, present first and retained renders with randomized A/B labels and matching framing. Ask which better satisfies the original request and why. A model's own preference is not a human rating. Keep factual geometry checks, subjective visual preferences and physical validation separate.

Suggested raw record columns:

`participant_id, task_id, condition, order, elapsed_seconds, completed_without_help, independently_checked_requirements_met, accidental_changes, understood_limits, observations`

Leave the records empty until someone actually performs the tasks. The next useful product change should address an observed difficulty or failure from these sessions.
